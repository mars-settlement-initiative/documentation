Mesa concepts used in this practical¶

Mesa supplies the simulation framework. You supply the meaning of each agent, its information and its decision rules. A multi-agent system (MAS) contains interacting agents whose actions affect a shared environment. Explorers and collectors have different roles but depend on each other to supply the base.

Registration and placement¶

In agents.py, we introduce two agent types, the ResourceAgent and the RobotAgent. Each agent is initialized bysuper().__init__(model) and registered with the model.

class ResourceAgent(mesa.Agent):
     def __init__(self, model, amount=RESOURCE_AMOUNT):
        super().__init__(model)
        ...

class RobotAgent(mesa.Agent):
    def __init__(self, model, energy=ROBOT_INITIAL_ENERGY):
        super().__init__(model)
        ...

ExplorerAgent and CollectorAgent inherit common functionality from RobotAgent.

Agent attributes¶

A RobotAgent holds the attributes (variables) energy, active and distance_travelled

    def __init__(self, model, energy=ROBOT_INITIAL_ENERGY):
        super().__init__(model)

        self.max_energy = energy
        self.energy = energy
        self.active = True
        self.distance_travelled = 0

A CollectorAgent additionally holds cargo, capacity and target_resource.

    def __init__(self, model, energy=100):
        super().__init__(model, energy)

        self.cargo = 0
        self.capacity = COLLECTOR_CAPACITY
        self.target_resource = None

The ResourceAgent holds amount and discovered.

    def __init__(self, model, amount=RESOURCE_AMOUNT):
        super().__init__(model)

        self.amount = amount
        self.discovered = False

Model attributes¶

The model, found in file model.py owns base_resources and known_resources.

self.base_resources = (
            initial_base_resources
        )

self.consumption_rate = (
            consumption_rate
        )

# Shared information available to robots.
self.known_resources = set()

A deposit owns amount and discovered.

self.model gives agents access to the simulation. Technical access to objects does not mean a policy should know everything: explorers must discover deposits, and collectors use known locations. Respect that information boundary.

Model¶

The model initializes Mesa with super().__init__(seed=seed). The supplied code uses self.random for random decisions. Record the seed to repeat a run.

In model.py, agents are placed in space.

 self.grid.place_agent(
                resource,
                position
)

Registration alone does not assign a grid location. After placement, self.pos gives its position.

Individual and shared state¶

A robot owns energy, active and distance_travelled; a collector also owns cargo and target_resource. The model owns base_resources and known_resources. A deposit owns amount and discovered.

self.model gives agents access to the simulation. Technical access to objects does not mean a policy should know everything: explorers must discover deposits, and collectors use known locations. Respect that information boundary.

Space and activation¶

These folders use mesa.space.MultiGrid, integer (x, y) positions and place_agent, move_agent and get_cell_list_contents. Several agents can share a cell. torus=False prevents wrapping at boundaries. Robot methods impose horizontal/vertical movement and energy costs; those are application rules, not automatic MultiGrid behaviour.

Other Mesa tutorials use CellAgent and mesa.discrete_space. Those have a different spatial interface; follow the MultiGrid interface in this practical.

An agent’s step() is one local turn. The model’s step() activates robots, applies consumption and records measurements. Shuffled activation is sequential: a later collector can encounter a deposit emptied earlier in the same tick.

From individual decisions to system outcomes¶

Explorers publish discovered positions in known_resources; collectors read this shared information. This resembles a shared information board, rather than explicit message passing or negotiation. Targets are intentions, not reservations. Two individually reasonable nearest-target choices can therefore overlap.

Use this explanation chain throughout the practical:

Individual decision → interaction pattern → colony outcome.

A target-selection rule might reduce overlapping journeys and change delivery timing. Test that hypothesis: fewer overlaps alone do not prove longer survival, and one deposit can supply more than one load.
